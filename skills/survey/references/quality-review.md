# Survey 质量评审与迭代

## 评分卡（Quality Scorecard）

对初稿逐项评分，汇总为总分（满分 55 分）：

| # | 维度 | 评分标准（1=差 / 3=及格 / 5=优秀） | 分值 |
|---|------|----------------------------------|-----|
| 1 | **文献覆盖度** | 奠基论文齐全；SOTA 覆盖近 1-2 年；无明显缺漏 | /5 |
| 2 | **技术深度** | 核心方法有原理解释，不只是名词罗列 | /5 |
| 3 | **分类体系** | Taxonomy 自洽、各类别无重叠、有代表性 | /5 |
| 4 | **数据准确性** | 数字（参数量/指标/时间）精确，有据可查 | /5 |
| 5 | **时间线完整性** | 从起源到最新进展，重要里程碑全覆盖 | /5 |
| 6 | **批判性分析** | 指出各方法优缺点和适用场景，不只是摘要转述 | /5 |
| 7 | **Benchmark/数据集** | 主流评测集和数据集列出，数字与原文对应 | /5 |
| 8 | **可读性** | 结构清晰，表格/图/正文搭配合理，语言精炼 | /5 |
| 9 | **引用规范** | 格式统一、信息完整、可追溯（见下方引用质量细则） | /5 |
| 10 | **引用覆盖率** | 每个核心技术声明均有对应引用，无裸声明 | /5 |
| 11 | **语言规范** | 中英混合符合规范，术语前后一致 | /5 |

**合格阈值：总分 ≥ 44，且任意单项 ≥ 3**

## 引用质量细则（重点检查项）

引用是学术 Survey 的骨架，每轮 Review 必须专项检查以下内容：

### 格式要求

每条引用必须包含以下字段，缺一不可：

```
**论文全名**（第一作者 et al., 发表机构/会议/期刊, 年份）[arXiv:XXXXXX 或 DOI]
```

**正确示例**：
> **Visual Instruction Tuning**（Liu et al., NeurIPS 2023）[arXiv:2304.08485]

**错误示例**（禁止）：
> LLaVA 论文提出了...  ← 缺少年份、arXiv
> 某研究表明...         ← 无引用来源
> [1][2][3]            ← 脚注编号，正文无法直接溯源

### 引用覆盖率检查清单

逐项检查以下位置，确保每条有据可查：

- [ ] 每个里程碑工作（时间线章节）：论文名 + 机构 + 会议 + 年份 + arXiv
- [ ] 每个方法子方向的代表性方法表：至少标注会议 + 年份
- [ ] 每个 Benchmark 数字（如"GPT-4o 在 MMMU 上达 69.1%"）：标注来源模型技术报告或评测论文
- [ ] 每个数据集：标注来源论文
- [ ] 技术结论性声明（如"MLP Projector 优于 Q-Former"）：标注做出该结论的实验论文

### 引用密度标准

- 正文叙述段落：每 2-3 个技术性声明至少有 1 条引用
- 表格中：每行代表性方法标注论文名（可简写）+ 年份
- 绝对不允许：连续 5 行以上没有任何引用的技术性叙述

## 迭代循环

```
初稿生成
    ↓
┌─────────────────────────────┐
│   第 N 轮 Review（对用户可见）│
│  1. 逐项评分（11 个维度）     │
│  2. 引用质量专项检查          │
│  3. 输出：当前版本摘要         │
│     + 评分卡（格式见下）       │
│     + 本轮低分项和修复计划     │
└─────────────────────────────┘
    ↓
总分 ≥ 44 且无单项 < 3？
  ├── 是 → 写入文件，输出最终评分卡
  └── 否 → 执行修复（见修复动作表）
              ↓
         更新文档内容（追加/重写对应章节）
              ↓
         进入第 N+1 轮 Review（最多 3 轮）
              ↓
         3 轮后仍未达标 → 写入当前最佳版本
                          在文档头部标注：⚠️ 待改进：[低分维度列表]
```

**关键原则**：每轮 Review 的评分卡和修复计划必须输出到对话中，让用户看到中间过程，不能等到最后才展示结果。

## 针对性修复动作

| 低分维度 | 具体修复方法 |
|---------|------------|
| 文献覆盖度 < 3 | WebSearch 该子方向 2023-2026 高引用论文 |
| 技术深度 < 3 | WebFetch 核心论文 Method 章节，补充方法原理和公式 |
| 分类体系 < 3 | 重新梳理 taxonomy，参考领域内已有 survey 分类方式 |
| 数据准确性 < 3 | 删除无法核实的数字，改为描述性表达；对关键数字 WebFetch 原文确认 |
| 时间线 < 3 | WebSearch 补搜断层年份的代表性工作 |
| 批判性分析 < 3 | 为每个子方向补充"局限性"段落；增加方法间横向对比 |
| Benchmark < 3 | WebSearch "{主题} benchmark leaderboard 2024"；补充评测数字 |
| 可读性 < 3 | 超过 5 行的列表转为表格；拆分过长段落 |
| 引用规范 < 3 | 逐一核查引用：补全论文名/**加粗**/会议/年份/arXiv 编号 |
| 引用覆盖率 < 3 | 逐段检查裸声明，补充对应引用；重点检查时间线、方法表、数字来源 |
| 语言规范 < 3 | 检查英文术语首次出现是否有中文注释；统一全文术语表达 |
